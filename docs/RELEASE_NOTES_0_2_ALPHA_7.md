# DotControl v0.2.0-alpha.7

[预发布版已公开](https://github.com/VeraPyuyi/DotControl/releases/tag/v0.2.0-alpha.7)，构建提交为
`3424e41a05b1858e12dc2137b3e0c3ceece078f0`。后续验收文档提交不改变安装包字节。

包含七项已确认的修复，以及当前用户会话中的后台运行管理。关闭控制台页面后代理继续运行；
Windows 由计划任务启动受控后台进程，Mac 由 LaunchAgent 管理异常恢复。明确退出后保持停止，直到本机重新打开或下次启用的登录启动。

## 本次修复

- 保留配置卸载后允许从可信安装记录重装；缺失旧主程序时允许修复，并准确报告回滚限制。
- 长任务达到回执上限后仍收集最终正文，分别标记正文、回执和单条输出截断。
- 重启后失效内存结果，包括退役任务；旧账本原始字节不改写、不重派任务。
- 保存允许公开的沙箱布局错误类别，避免笼统失败且不公开私密上游错误。
- 忽略共享列表过期分页响应，保留当前筛选及已选候选。
- 历史接口故障或配置变化使就绪检查失效，防止旧请求覆盖新状态。

## 后台与按需连接

Windows 使用当前用户的计划任务，Mac 使用用户 LaunchAgent；不要求管理员、账户密码或
系统服务权限。Windows 后台进程按实际代理退出结果等待 60 秒重试，连续失败最多重试 3 次，不把计划任务的
RestartOnFailure 配置视为进程崩溃恢复的证明。旧登录启动入口纳入升级事务及清理检查，
不与新版并行拉起代理。
异常恢复不会解除暂停、恢复撤销、扩大共享清单或重放结果不确定的任务。

发送包含目标 DotControl 插件的连接请求后，先检查 devices 的设备身份、新 nonce 与实际能力。
源 Dot 保持连接原电脑。连接请求本身不创建 Codex 任务；读取历史与终端任务继续受目标电脑
本机权限约束。MCP 保持 13 个工具，升级后需在官方插件设置刷新工具并在新会话核对。

这不是远程开机或唤醒功能：关机、休眠、未登录或代理完全退出时，单凭 @ 无法启动接收端。
插件说明引导模型调用，不提供“选中 @ 就执行”的系统钩子。Mac 终端与原生 Computer Use
继续受各自验收开关约束；SSH／实验助手与审批转发维持下线。

## 发布与升级

已提供 Windows x64 EXE、Mac ARM／Intel DMG、安装助手、许可证和校验和，共 11 个文件；
全部文件已从公开 Release 重新匿名下载并核对摘要。
升级顺序为校验新版、暂停自动拉起、正常退出旧代理、验证新版、恢复后台管理、清理旧程序。
设备、隧道、系统凭据、端口、终端绑定、暂停／撤销、共享清单和历史记录保留。
旧清单与新安装器兼容；新增安装归属字段不能由旧安装器回读，不使用旧安装器管理新清单。

安装包未配置发布者签名／公证；仍校验固定依赖及上游 Mac 驱动签名。
本机 Windows 已使用公开 EXE 升级并清理 alpha.6 托管目录，白名单仍为修订号 3、2 个会话。
计划任务使用普通交互用户身份，旧 Run 入口已移除。现有插件已刷新并显示 13 个工具。
源 Dot 保持 Mac attached，实际 Windows Codex 任务返回系统版本、X64 和命令退出码 0，
同一作业的独立查询一致；运行时 verification 仍保留 unverified，不改写为已验证。

三平台原生测试、竞态检查、静态检查、后台生命周期及每平台 8 项隔离安装检查通过。
Mac Intel 公开包首次清理检查返回 `startup_references_unavailable`，新版指针和旧 manifest 尚在，
当次删除被保护检查阻止；此前清理阶段可能已删除部分已校验文件，不能声称旧文件全部保留。
同一公开字节仅重试该失败 job 后通过。首次失败根因尚未确定，未放宽清理保护；系统启动引用
无法完整确认时，仍可能显示清理待完成。见[首次记录](https://github.com/VeraPyuyi/DotControl/actions/runs/38509150092/job/115673413936)。

用户 Mac 未修改；Mac runner 检查不代表用户 Mac 真机权限或云端验收。PR #1 未合并，旧
发布文件未覆盖。具体证据及剩余限制见[支持矩阵](RELEASE_SUPPORT.md)。
