# Dot task event subscriptions

`internal/dotevents` implements the subscription store and outbound webhook transport for MCP Events (2026-07-28), following the saved routing design and OpenAI's [MCP Events guide](https://developers.openai.com/plugins/build/mcp-events). Integration into MCP discovery and the runtime worker is a separate task. This package does not implement poll, stream, gap recovery, queue execution, or model readiness.

`Open(absoluteDir, key, delivery)` requires a caller-supplied 32-byte key. A nil delivery or zero-value `Delivery` uses public HTTPS with normal certificate verification. The package has no production switch to permit private callbacks. Tests inject an unexported HTTP client with explicit local fixture routing and trusted fixture certificates.

The authenticated adapter supplies `principal`; the caller's `arguments.queue_id` must equal that principal. `List` advertises `dot.task.available` before a subscription exists. `Params` accepts `name`, `arguments:{queue_id}`, `delivery:{mode:"webhook",url,secret}`, optional null `cursor`, and raw `ttlMs`. Its JSON decoder rejects unknown/duplicate fields and null required objects. The adapter must enforce the request byte limit before decoding too. Omitted or null TTL means one hour, with an allowed range of one minute to one day. No non-expiring grant is supported. Secrets use `whsec_` plus standard base64 encoding of 24–64 bytes. URLs are limited to 2048 bytes and params to 16 KiB.

Subscription identity is SHA-256 over the principal, event, arguments, mode, and exact callback URL, excluding the secret and TTL. Refresh keeps that identity. The encrypted state is persisted before callback verification. Every refresh gets a random generation; publishing the verification result requires the same generation after network I/O. Pause invalidates all callback verifications and generations, including across disable/re-enable. Unsubscribe selects the same identity without requiring a secret and is idempotent. The integration adapter must map the official unsubscribe request into this internal selection struct.

Verification posts signed `{ "type":"verification", "challenge":"<random nonce>" }`. The unique nonce is used for one attempt bounded to ten seconds, below the five-minute verification maximum. A successful response must be 2xx with bounded JSON `{ "challenge":"<same nonce>" }`; comparison uses constant time. An event occurrence contains `eventId`, `name`, an RFC3339 timestamp, `data:{queue_id,job_id,mode}`, and `cursor:null`. It never includes task prompts. Occurrence bytes are persisted on the first attempt and reused for retries.

Standard Webhooks signs the exact UTF-8 bytes with HMAC-SHA256 over `webhook-id.webhook-timestamp.body`. `webhook-timestamp` uses Unix seconds. The `webhook-id` is derived from subscription ID plus notice event ID, so each subscription has a distinct stable delivery identity. Each POST includes `X-MCP-Subscription-Id`. Refreshing a secret preserves the previous secret for dual signatures during a 60-second grace window. Expired subscriptions do not deliver.

Every `Deliver` visits all matching verified subscriptions in sorted identity order, making at most one HTTP attempt per subscription. It reserves attempts atomically under the cross-process state lock before I/O. Parallel workers receive `in_flight` with a retry delay while a reservation is active; a crashed worker consumes an attempt and its reservation expires after eleven seconds. A 2xx records receipt only. 410/413 and other 4xx are terminal, except 429. Network failures, 5xx, and 429 permit three retries after 1s, 2s, and 4s, for four total attempts. No sleeps or background worker exist here: the caller/outbox schedules `Error.RetryAfter`. An early call returns the remaining delay without sending. Terminal and acknowledged records suppress further sends. There is no exactly-once guarantee after an ambiguous callback outcome. Storage capacity is 100 subscriptions and 1000 delivery records; reaching the delivery bound fails closed and requires a future explicit retention policy.

Outbound transport disables environment proxies, redirects, connection reuse, and implicit DNS during socket dialing. Every new connection resolves with context, rejects the entire answer set if any address is non-public, then dials validated literal IPs while HTTP retains the original hostname for TLS SNI and certificate checks. Loopback, private, link-local, CGNAT, documentation, reserved, multicast, unspecified, IPv6 transition, and special-purpose ranges are rejected. Query strings are allowed and never copied into errors. Timeouts are at most ten seconds; response headers and verification bodies are limited to 16 KiB; event response bodies are discarded without reading; event bodies are capped at 256 KiB.

State uses AES-256-GCM, private directory/file permissions (protected current-user DACL on Windows), regular-file and hardlink checks, a five-second bounded flock, synced temporary files, and atomic replacement. Separate files are `events.state.de`, `dot_events.lock`, and `dot_events.initialized`. Missing state after initialization and invalid ciphertext fail closed. No queue package private functions or files are used.

Errors are stable `dot_events_<code>` values with optional retry duration and no callback URL, secret, response page, or filesystem path. `Status` distinguishes subscription and callback verification; `DotReady` is always false. The runtime must establish real readiness separately through authenticated claim/completion of a probe, and propagate pairing authorization changes into `SetEnabled` before allowing operations.

Offline verification: `go test ./internal/dotevents` and `go test -race ./internal/dotevents`. Tests cover official wire fields, JSON challenge replies, exact HMAC bytes, rotation, persistence, expiry, unsubscribe, pause during verification/delivery, competing refresh, duplicate acknowledgements, multiple subscriptions, atomic reservations, bounded retries, production public-address checks, DNS rebinding, redirect rejection, cross-process locks, and corrupt/missing state. Full repository tests belong to the integration controller.
