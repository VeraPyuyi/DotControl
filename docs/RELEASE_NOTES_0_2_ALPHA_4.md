# DotControl v0.2.0-alpha.4

此预发布版提供 Windows x64、Mac Apple Silicon 和 Mac Intel 安装包及 Codex 安装助手。从 `codex/windows-codex-delegation` 分支的 `728d152430fb6a800b570e78c1f74e6d3700aee4` 构建；PR #1 仍未合并，alpha.3 资产和历史验收记录保留。本轮未修改用户正在使用的 Mac。

## 本版变化

- 网络连接默认 `auto`：优先使用进程环境中适用于 HTTPS 控制连接的代理，再读取当前用户系统中适用于该连接的静态代理及绕过规则；无代理时直连。不会回退到 `HTTP_PROXY` 或系统中仅用于 HTTP 目标的设置。本机向导可选择自动、直连或手动 HTTP / HTTPS 代理。
- 代理仅用于官方隧道的云端控制连接，通过环境变量引用传递。本机服务始终直连，不修改系统代理、DNS 或 TLS。
- 云端在线根据当前隧道进程的详细健康信息和近期成功轮询判断。就绪同时要求本地就绪和有效云端证据；成功记录超过 `max(90 秒, 2 × 轮询 deadline)` 后不再有效。`/readyz` 成功不再作为云端在线证据。
- 向导区分本地服务、云端隧道与源 Dot 调用，并显示正在使用的连接来源。网络设置保存或检测到代理变化后标记待应用，不结束运行中的客户端；最新设置在隧道下次启动时生效。
- `doctor --online` 的 `official_tunnel_doctor=configuration_validated` 仅表示配置检查通过；实际运行中的云端证据由 `tunnel_cloud_connection` 单独返回。
- 保持 14 个 MCP 工具，网络设置仅在本机开放。设备身份、隧道、系统凭据、暂停／撤销、终端权限配置、共享范围及动作历史继续保留。

## 使用与边界

已有设备选择保留原设备。自动模式通常无需额外操作；PAC、仅 SOCKS 或需要交互认证的代理会明确提示限制。手动地址不接受用户名和密码，认证在本机代理程序处理。详见[安装指南](INSTALL.md)与[网络连接说明](NETWORK.md)。

固定官方客户端 0.0.16 没有可证明请求无损结束的排空接口：短暂空闲不能证明全部工作已处理，退出信号也可能取消在途请求。本版不热切换正在运行的客户端；新设置持续待处理，直到子进程自然退出后的重启或下一次明确的本机重启。不要为应用设置强制结束进程、另起同隧道客户端或重发未知任务。下次启动后先等待新的成功轮询，再在源 Dot 核对本次真实插件调用；升级后刷新官方插件工具目录。

本版不增加 SSH、Computer Use 或远程审批能力，相关未验收功能继续关闭。终端委派、历史读取、桌面操作和源端图片显示分别验收。安装包尚未配置发布者签名或公证；Cua 上游签名失败时仍停止，不重签或关闭系统检查。
