# DotControl 0.2：安装和连接

先查看 [当前支持与验收状态](RELEASE_SUPPORT.md)。下载入口为 [GitHub Releases](https://github.com/VeraPyuyi/DotControl/releases)。只使用已发布的对应系统安装包，没有对应产物时不用开发构建代替。

## 1. 安装

- Windows 11 x64：打开 DotControl-0.2.0-alpha.6-windows-amd64-setup.exe。
- Mac Apple Silicon：打开 DotControl-0.2.0-alpha.6-macos-arm64.dmg 内的 DotControl Setup.app。
- Mac Intel：使用 DotControl-0.2.0-alpha.6-macos-amd64.dmg。

alpha.6 [发布入口](https://github.com/VeraPyuyi/DotControl/releases/tag/v0.2.0-alpha.6)，三个安装包及安装助手均附校验和；实际公开下载与包内验证结果见支持矩阵。各平台实际验证范围见[支持矩阵](RELEASE_SUPPORT.md)。缺少对应资产或摘要时停止，不替换为其他版本并声称完成本版安装。

安装器自动校验随包组件、识别旧设备、安装到当前用户目录并启动本地向导。发现多个已有设备时选择要升级的设备，不删除状态目录重新安装。正常安装无需终端、Go、Python、Homebrew 或 Xcode。首次发布未配置发布者签名或公证，系统可能显示来源提示；上游 CuaDriver 签名校验失败则停止。

Mac 的 CuaDriver 固定放在 /Applications/CuaDriver.app。活动检测和菜单程序位于当前用户的 Applications。按向导打开辅助功能、屏幕录制和输入监控设置，由你完成系统授权。授权后点击“检查并修复连接”。若系统要求退出重开，应完成该步骤。

## 2. 连接账号

向导提供三个准确的官方入口，并可复制设备名称和隧道编号：

1. [创建 Secure MCP Tunnel](https://platform.openai.com/settings/organization/tunnels)：每台目标电脑使用独立的 tunnel_… 编号。
2. [创建运行密钥](https://platform.openai.com/settings/organization/api-keys)：仅授予 Tunnels 的 Read + Use 权限。把密钥填入本地向导的隐藏输入框，不要发到聊天、命令行、截图或日志中。
3. [添加私有插件](https://chatgpt.com/plugins)：选择自定义 MCP 服务器和 Tunnel，填写该设备名称与相同隧道编号，并完成官方确认。

在“连接设置”点击“保存并连接”。密钥保存在 Windows 凭据管理器或 Mac 钥匙串。已有配置时留空不会清除密钥。官方账号权限不足时保留当前进度，不需要组织管理员密钥。

安装 Codex 引导插件后，可以说“帮我安装并连接 DotControl”。它使用相同安装器和正常浏览器工具协助填写；登录、密钥录入和系统权限仍由你完成。插件源码位于 plugins/dotcontrol-onboarding，仓库同时提供 Codex marketplace 描述。

### 网络连接

向导的“连接设置 → 网络连接”默认选择 **自动使用已有代理**：先使用当前进程中适用于 HTTPS 控制连接的代理环境变量，再读取当前用户系统中适用于该连接的静态代理；没有代理则直连，匹配绕过规则时也直连。仅有 `HTTP_PROXY` 或系统中仅用于 HTTP 目标的设置不会用于 HTTPS 控制连接。可在本机改为 **直连** 或填写无用户名、密码的 **手动 HTTP / HTTPS 代理**。仅影响官方隧道的云端控制连接，本地向导、MCP 和健康检查始终直连，不修改系统代理、DNS 或 TLS 设置。

PAC、仅 SOCKS 和交互认证未实现自动支持。请按返回的具体原因，在本机代理程序处理或选择已可用的静态 HTTP / HTTPS 连接，不把认证信息发到聊天。保存后显示“新的设置将在隧道下次启动时应用”：当前官方客户端不能保证无损热切换，DotControl 不因网络设置变化结束运行中的客户端。最新设置在子进程自然退出后的重启或下一次明确的本机重启时应用；即使暂时空闲也可能一直待处理。不要为消除该状态强制结束进程或重发任务。详见[网络模式、状态与诊断](NETWORK.md)。

## 3. 验证并启用

在“概览”点击“复制测试指令”，发给源电脑上的官方 Dot。保持官方连接在源电脑，让 Dot 通过目标设备的插件调用 devices，核对名称、设备 ID、随机值。

向导分别显示本地服务、云端隧道和源 Dot 调用。本地就绪只证明本机入口可用；云端在线还要求当前隧道进程的健康详情包含近期成功轮询；源 Dot 必须另外核对本次插件返回。进程存在、本地 `/readyz` 为 200 或 `doctor --online` 的配置检查成功均不能单独证明云端在线。插件工具改为 13 个，升级后在官方设置刷新工具并核对实际会话目录。

Windows 的终端任务可在本机独立启用，不要求 Cua Driver 或 SSH。按向导完成本机 Codex 终端配置和当前目录授权后，再启用该能力；SSH 与服务器访问按实际任务另行配置。历史共享独立且可选，由本机明确选择共享范围。

桌面能力须单独验收：本机检查通过后点击“恢复访问”，让 Dot 观察无害窗口，再做一个有明确新状态的动作。动作使用新的观察与唯一动作编号；结果为 unknown 时先重新观察，不能重发。只有实际在源 Dot 中看到原始图片后，才点击“确认已在源 Dot 看到图片”。“隧道在线”“插件已调用”“MCP 返回图片”“源 Dot 显示图片”分别记录，不能相互替代。官方 Codex Computer Use 尚未开放；旧审批转发已下线；检测到 App Server 或工具不等于完成相关验收。

## 控制台布局

已配置设备默认显示概览。连接设置管理隧道、密钥、代理与诊断；Codex 管理终端和高级项目权限；会话共享管理只读范围。状态定时刷新不会覆盖表单或候选，权限变更需本机明确操作。旧 SSH／实验助手及审批入口已下线，原文件和记录保留。

## 日常管理与恢复

关闭网页不停止代理。通过 Windows 托盘或 Mac 菜单栏重新打开向导、暂停、继续、修复或退出。随用户登录启动，不作为系统后台桌面服务运行。修复保留身份、凭据、暂停/撤销状态和动作记录；连接失败退避重试，未知动作不重放。

脱敏诊断按钮下载版本、阶段、错误类别和必要状态，不包含密钥、输入正文或截图。签名失败、密钥失效、DNS、TLS、权限未知和暂停分别显示；不要通过关闭 TLS 校验、重签 CuaDriver 或改系统安全策略解决。

再次运行完整安装包可修复程序文件。旧版正在执行时先正常停止任务；没有新管理接口的 0.1 代理须先退出。已有网关配置的迁移目前拒绝执行，原配置保持不变。

升级先等待已接受任务完成和旧代理及其子进程正常退出，再检查新代理的设备身份、版本和实际程序路径。退出请求被拒绝时不改写配置、不调用取消任务的普通退出接口。健康检查失败会按私有恢复记录还原原配置字节、程序引用和登录启动设置；恢复记录也用于处理中断后的重试。已有设备原先关闭登录启动时，升级保留关闭状态；首次安装默认启用登录启动。

同一设备目录的安装与恢复串行执行；普通安装还串行保护当前用户的登录启动和 Mac 组件。登录启动已指向另一设备时停止并要求选择正确实例。恢复记录保留已观察到的子进程，确认全部退出之前不重新启动旧代理。

新版通过健康检查后才清理安装清单记录的旧程序文件。程序进程或登录启动仍有引用、文件内容改变或引用无法确认时，显示“旧程序清理待重试”，新版保持启用。重试先完成此前清理，不能回退到已经开始清理的旧版本。用户附加文件、设备身份、隧道、系统凭据、暂停/撤销状态、共享范围与动作记录保留。Mac 的共享 CuaDriver 应用不属于旧版本清理范围。

## 高级维护

以下为维护命令，不是正常用户安装步骤。对同一设备始终使用同一个 --state 目录：

- dotcontrol install --bundle <预构建组件目录>
- dotcontrol onboard
- dotcontrol repair
- dotcontrol repair --bundle <预构建组件目录>
- dotcontrol uninstall
- dotcontrol codex-probe --binary <官方 Codex 绝对路径> --working-dir <独立诊断目录>

uninstall 只移除本项目管理的程序文件和登录启动设置，保留设备记录与凭据；不提供隐式清除。请勿手工删除账本以解决结果不确定。安装器的 --verify-payload 仅校验实际包内文件，不安装、不启用桌面任务。

后续源码已修复“保留配置卸载后重装”与“旧主程序缺失时修复”的阻塞，尚未包含在 alpha.6
安装包中。恢复安装需要此前成功安装与状态目录绑定的来源记录；来源不明或更旧的无绑定
卸载记录仍需明确迁移。缺失旧程序时仍核实进程退出；新版失败保留配置并报告旧程序无法
恢复，不伪称旧版已运行。新增绑定不支持旧安装器回读，勿用旧安装器管理新清单。
Windows 运行中程序的自卸载占用仍待实际核实。详见 [源码复盘与限制](REVIEW_0_2.md)。

Windows 非托管开发版本迁入托管目录时，先等待任务结束并从原入口正常退出旧代理，再指定原程序的绝对路径：

```text
DotControl-0.2.0-alpha.6-windows-amd64-setup.exe --install --state "<原设备目录绝对路径>" --program-root "<托管程序目录绝对路径>" --legacy-executable "<原 dotcontrol.exe 绝对路径>"
```

安装器确认候选为普通无链接的 DotControl 程序，并记录 SHA-256；失败时可重新启动原程序。它不会自动删除非托管程序或其目录。非托管迁移仅支持 Windows；Mac 托管升级继续使用原设备目录。不能通过删除原设备目录绕过迁移选择。

自动验收可使用完整安装包的 `--install --state <绝对路径> --program-root <绝对路径> --no-start`，返回单个 JSON 结果。`--no-start` 仅用于隔离测试：校验包和二进制版本，更新所选隔离目录，不启动代理、不修改登录启动、不创建凭据、不安装共享 Mac 组件；结果中的 `runtime_verified` 为 false。已提交的清理阻塞返回 `installed: true, cleanup_pending: true`，无需回退新版。`--extract-payload <空目录绝对路径>` 只展开并校验实际嵌入文件，可用于隔离验收。两个维护入口均不打开界面，不接受外部 `--bundle` 替换安装包内载荷。通常使用双击安装。

0.1 源码安装和历史迁移细节已移到 [旧版说明](INSTALL_0_1_LEGACY.md)。

`--no-start` 遇到正在运行的设备或需要真实运行时恢复的旧事务会直接拒绝，不访问凭据、不发送退出请求。请给验收使用独立目录；普通设备恢复仍使用正常安装入口。
