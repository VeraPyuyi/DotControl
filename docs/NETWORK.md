# 网络连接与云端状态

alpha.4 将本地服务、云端轮询和源 Dot 调用分开显示。网络设置仅控制官方隧道的云端控制连接；不会更改系统代理、DNS、TLS、Codex、SSH 或桌面权限。各平台实际验收见[支持矩阵](RELEASE_SUPPORT.md)。

## 选择连接方式

在受保护的本机向导中打开“网络连接（通常无需修改）”。已有配置没有网络字段时按 `auto` 读取，保存时保留其余设备设置。

| 模式 | 行为 |
|---|---|
| 自动 `auto`（默认） | 先读取 DotControl 当前进程的代理环境变量，再读取当前用户系统中的静态 HTTP / HTTPS 代理；没有代理则直连 |
| 直连 `direct` | 不使用进程或系统代理 |
| 手动 `manual` | 使用本机页面保存的 HTTP / HTTPS 代理地址，地址中不能包含用户名或密码 |

自动模式的环境变量优先级为 `DOTCONTROL_CONTROL_PROXY`、`CONTROL_PLANE_HTTP_PROXY`、`HTTPS_PROXY` / `https_proxy`、`HTTP_PROXY` / `http_proxy`、`ALL_PROXY` / `all_proxy`。仅接受 HTTP / HTTPS 代理；发现不支持或无效的值会给出原因，不静默尝试其他路线。进程环境中的认证值仅用于子进程环境，不写入设备配置或诊断。

Windows 读取当前登录用户的 Internet Settings；Mac 读取系统当前生效的静态代理。自动模式识别 `NO_PROXY` / `no_proxy`，以及所选系统代理的绕过规则；手动模式也尊重进程的 `NO_PROXY` / `no_proxy`。规则匹配云端控制服务时直接连接。DotControl 通过 `--control-plane.http-proxy env:DOTCONTROL_CONTROL_PROXY` 向官方客户端传递代理引用，命令行不含代理值。本机向导、MCP、隧道健康接口和桌面驱动连接始终直连，不继承云端代理。

本版不执行 PAC / 自动发现脚本，不支持仅 SOCKS 的配置，也不完成交互认证。系统配置提供可用的静态 HTTP / HTTPS 代理时可使用该静态地址；只有 PAC、SOCKS 或需要本机认证时明确报告限制。请在本机代理程序解决，或在向导选择已有的可用静态代理。不要把代理密码填入地址、聊天或日志，不关闭 TLS 检查。

保存设置后，向导可能显示“新的连接设置等待安全重连”。设置已保存不表示新路线已连接。隧道仍在长轮询、队列有任务、正在执行或交付响应时继续等待；缺少完整的空闲证据时也不强制切换。重连保持单一受管理的隧道进程，不取消已接受任务、不重放未知请求，也不解除暂停或撤销。等待本身不构成连接失败。

## 如何判断在线

| 状态 | 能证明什么 |
|---|---|
| 本地服务就绪 | 本机向导和代理可响应；不证明云端看到设备 |
| 云端隧道在线 | 当前隧道进程本地就绪，且健康详情包含近期成功轮询，没有更新的失败证据 |
| 源 Dot 调用 | 本机曾收到 MCP 设备查询；源端仍须核对本次设备 ID、nonce 和返回结果 |
| 图片返回 / 图片显示 | MCP 返回图片和源 Dot 实际显示原图是两个独立结果 |

云端状态来自当前进程的 `/health?details=true`，校验进程实例、启动时间、快照和控制服务轮询详情。成功轮询的最大有效年龄为 `max(90 秒, 2 × 轮询 deadline)`。没有成功记录、记录过期、出现新失败、详情缺失或进程不匹配时，不显示为已连接；重启前的成功记录不能沿用。组合就绪值要求 `local_ready` 和有效的云端成功轮询同时满足。

`/readyz` 返回 200、隧道进程存在和官方 `doctor` 成功都不能代替上述证据。`doctor --online` 的 `official_tunnel_doctor=configuration_validated` 只表示配置通过官方检查；`tunnel_cloud_connection` 单独读取正在运行的 DotControl supervisor 状态。没有运行服务或只有旧版就绪状态时，云端连接仍是不可用或未确认。

源端工具目录仍须单独核对：本版 MCP 保持 14 个工具，网络设置只在本机页面开放。升级后在官方插件设置刷新工具，在实际源端会话检查目录；不要用历史 `devices_seen` 或本地能力状态代替。

## 诊断与恢复

先查看向导中的具体状态和脱敏诊断，再选择本机处理方式。DNS、TLS、超时、代理认证、运行密钥或隧道权限、成功记录过期分别报告。`requires_local_proxy_auth` 需要本机处理；运行密钥仅在向导的隐藏输入框更新，不通过聊天传递。

保留设备、插件和隧道身份，通过向导保存连接方式或正常修复。不要同时启动第二个客户端占用同一隧道，不为重连强制终止正在处理请求的进程。恢复后先等待新的成功轮询，再由源 Dot 调用同一插件验证；终端任务、桌面动作和图片交付继续分别验收。
